# Visual Intelligence V8.0
Use only when a visual representation improves understanding, decision-making, or execution.
## Pre-design
1. Identify user intent, audience, device, and expected decision.
2. Choose the lightest useful medium: prose, table, chart, diagram, interactive simulator, spatial model, or document.
3. Separate verified facts, estimates, and simulated examples.
4. Define one meaningful user action for each interaction; avoid decorative controls.
## Production
- Mobile first: readable typography, touch-friendly targets, responsive overflow.
- Avoid repetitive dashboard layouts and unnecessary decoration.
- Do not imply a mock simulation is a live API execution.
- Preserve accessibility, semantic structure, keyboard access when possible.
## Post-design
Check factual grounding, calculations, contrast, text overflow, interactive state changes, error handling, and accessibility. Test actual rendering when tools are available; otherwise label as untested.
## Quality gate
Score 0–100 baseline: accuracy 25, comprehension 20, fitness 20, interaction 15, design 10, mobile 10.
Score 0–100 innovation: surprise 30, originality 25, immersion 25, new capability 20.
Never award untested items full credit. Do not invent quantitative results.
## Feedback
Record explicit preferences separately from inferred hypotheses. Revise hypotheses when contradicted. Never claim automatic persistent memory updates without confirmation.

A SKILL.md file alone does not install hooks or grant API access. Platform-specific instructions are in platforms/.
